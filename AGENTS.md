# Project Stack

Use only the technologies listed below when generating code for this project.

## Backend
- Go (Golang)

## HTTP
- chi router (`github.com/go-chi/chi/v5`)

## Database
- PostgreSQL
- Redis
- pgx (`github.com/jackc/pgx/v5`)

## Migrations
- goose (`-- +goose Up` / `-- +goose Down` format)

## Configuration
- cleanenv (env vars, `.env` file via godotenv)

## Testing
- testify (`github.com/stretchr/testify`) — `assert` / `require` / `mock`
- mockery v3 (`github.com/vektra/mockery/v3`) — mock generation

## Infrastructure
- Docker, Docker Compose
- GitHub Actions

## Observability
- OpenTelemetry Collector — single ingest point, fans out to the backends
- Jaeger (traces), Prometheus (metrics), Loki (logs), Grafana (UI)
- OpenTelemetry Go SDK (`go.opentelemetry.io/otel`) — app pushes OTLP to the collector
- otelhttp (`go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp`) — HTTP server instrumentation
- otelpgx (`github.com/exaring/otelpgx`) — pgx tracing

# Commit Messages

- Title under 50 chars, starting with `feat: `, `fix: `, or `refactor: `
- Blank line between title and body
- Body is lowercase, casual, to the point — no corporate tone
- No bold headers, no bullet categories like **Infra:** or **Config:**
- No specific file or variable names
- No phrases like "this commit", "this change", "added support for"
- Each body line is a separate thought, separated by a newline
- Mention what was done and why it matters, not just what files were touched
- Do not wrap the message in a code block

# Architecture

Clean Architecture with 4 layers. Always respect the dependency direction:

```
delivery/http → usecase → domain ← repository
```

- `internal/delivery/http/<domain>/` — HTTP handlers, parse requests, call usecases
- `internal/usecase/<domain>/` — business logic and validation
- `internal/domain/<domain>/` — entities + repository interfaces (no imports from other internal packages)
- `internal/repository/postgres/` — concrete DB implementations
- `internal/adapters/` — external integrations (JWT, etc.)
- `pkg/` — shared infrastructure (config, logger, postgres pool)
- `internal/generated/api/` — types generated from `api/openapi.yaml` via `oapi-codegen` (`make gen`)
- `internal/generated/mocks/` — mocks generated from every interface under `internal/` via `mockery` (`make mocks`)
- `deploy/observability/` — collector, Prometheus, Loki and Grafana configs for the local stack (`make obs-*`)

# Patterns & Conventions

## Adding a new domain feature
1. Define entity + repo interface in `internal/domain/<domain>/`
2. Implement usecase in `internal/usecase/<domain>/`
3. Implement repo in `internal/repository/postgres/`
4. Add handler in `internal/delivery/http/<domain>/`
5. Wire up in `cmd/service/main.go` and register routes in `internal/delivery/http/router.go`
6. Write migration in `migrations/`

## Naming
- Handlers: `Handler` struct, methods named `Create`, `List`, `Update`, `Delete`
- Services: unexported `service` struct, `New()` factory returning interface
- Repos: exported `*Repository`, methods like `Create`, `FindByID`, `Update`, `Delete`
- Usecase DTOs: `Input` / `Output` suffixes

## Error handling
- Domain-level sentinel errors in `internal/domain/<domain>/errors.go` (e.g. `ErrNotFound`)
- Usecase-level validation errors (e.g. `ErrInvalidName`, `ErrPasswordTooShort`)
- Repos wrap DB errors into domain errors; usecases wrap domain errors if needed
- Error wrapping: `fmt.Errorf("repo: create: %w", err)`
- Handlers use `errors.Is()` to map to HTTP status codes

## HTTP responses
- Success with body: write JSON + status code
- Success no body: `204 No Content`
- Error: `{"error": "message"}` via `httputil.ErrResp()`
- Common codes: 201 create, 204 update/delete, 400 validation, 401 auth, 404 not found, 500 unexpected

## Context
- User ID injected by auth middleware, read via `middleware.UserIDFromContext(ctx)`
- Always pass `ctx` through all layers

## Database
- All queries use parameterized arguments (no string formatting for values)
- Soft delete via `deleted_at TIMESTAMPTZ` — always filter `WHERE deleted_at IS NULL`
- Archive via `archived_at TIMESTAMPTZ` (separate from delete)
- UUIDs for all primary keys (generated by DB default)

## Auth
- Access token: JWT, 15m TTL
- Refresh token: stored as SHA256 hash in DB, 720h TTL, max 5 per user (oldest pruned)
- Bearer token in `Authorization` header
